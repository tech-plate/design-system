# タイポグラフィ

**独自の `fontSize` スケールを定義しない。** Tailwind 標準スケールを「用途」にマップして使う。
サイズの種類を増やすのではなく、用途ごとにどのクラスを使うかを決め打ちすることで一貫性を出す。

フォントファミリは各プロダクトで 1 つの Sans と 1 つの Mono を設定し、`body` に Sans を適用しておく。
本文で `font-sans` を明示する必要はない。

## 1. サイズの使い分け

| 役割 | クラス | 補足 |
|------|--------|------|
| ページ見出し（h1 相当） | `text-2xl font-bold` | 画面タイトル。**1画面に1つ** |
| セクション見出し（h2 相当） | `text-xl font-semibold` | Card のタイトル等、まとまりの長 |
| 小見出し（h3 相当） | `text-lg font-medium` | サブセクション |
| 本文・フォーム値 | `text-base` | 既定。多くの入力・表示はこれ |
| 補助テキスト・ラベル・キャプション | `text-sm` | フィールドラベル、説明文、テーブルセル |
| 注釈・メタ情報 | `text-xs` | タイムスタンプ、件数、軽微な補足 |
| 転記・目視照合する英数字文字列 | `font-mono`（`text-*` と併用） | API キー・URL・トークン等。0/O・1/l の誤読防止 |

**迷ったら `text-sm`。** 業務画面の情報密度では、ラベル・テーブルセル・説明文の大半が `text-sm` に収まる。
「本文なのか補助なのか」で迷ったときは `text-sm text-muted-foreground` に寄せる。

## 2. ウェイトと色の組み合わせ

- **強調はウェイトで表現する**（`font-medium` / `font-semibold` / `font-bold`）。**色での強調は最小限**にする。
  色は意味（成功・警告・エラー・リンク）を伝えるために取っておく。
- 補助テキストは `text-sm text-muted-foreground` をセットで使う（色は [color.md](./color.md) のトークン）。
- 一画面で使う見出しサイズの段階は **2〜3 段まで**に抑え、サイズの乱立を避ける。
- ウェイトも 3 種（`normal` / `medium` / `semibold`）＋ページ見出しの `bold` までに抑える。

## 3. mono の使いどころ

`font-mono` は **転記・目視照合する英数字文字列だけ**に使う。

| 用途 | mono |
|------|------|
| API キー、トークン、URL、ハッシュ、識別コード（人が目で照合する） | ✅ 使う |
| 金額、ポイント、件数などの数値 | ❌ 使わない（Sans のまま） |
| ID（画面上で照合しない内部 ID） | ❌ 使わない |

金額や数値を等幅にしたくなるのは「桁を揃えたい」からだが、それは**右寄せ**と
`tabular-nums`（`font-variant-numeric`）で解決する。書体を変える必要はない。

## 4. やらないこと

- ❌ `style={{ fontSize: "13px" }}` のような px 直書き → §1 の表のクラスから選ぶ
- ❌ `text-[15px]` などの任意値クラス → 標準スケール（`text-sm` / `text-base` 等）に寄せる
- ❌ `font-family` の直接指定 → Sans は既定、等幅は `font-mono`
- ❌ 独自の `fontSize` トークンを Tailwind config に足す → 標準スケールで足りる
- ❌ 金額・ポイント・ID 等の数値への `font-mono`

### 例外

高密度グリッド（絶対配置・px 寸法のセルやバーと同居する最小ラベル）に限り、
`text-[10px]` 相当の任意値やインライン `fontSize` を許容する。
12px 未満の表示が物理的に必要で、標準スケールでは収まらないケースのため。

**乱用しない。** 一覧・フォーム等、密度制約のない箇所では通常どおり標準スケールに従う。
