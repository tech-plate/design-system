# ナビゲーション

メニュー（サイドバー・グローバルナビ）の組み立て方。
**メニューはオブジェクト（名詞）で組む。** 動詞・役割・データの性質で組まない。

色は [color.md](./color.md)、余白は [spacing.md](./spacing.md)、文言の書き方は [typography.md](./typography.md) を参照。

## 0. なぜオブジェクトで組むのか

メニューが読みにくくなるとき、原因はたいてい**分類軸が複数混ざっている**ことにある。
「業務か設定か」「自分のものか全体か」「admin か一般か」「マスタかトランザクションか」を
同じ階層に並べると、利用者は「探しているものがどの軸に属するか」を先に当てないと辿り着けない。

利用者が探すのは**オブジェクト**（顧客・予約・経費申請・スタッフ）であって、
そのオブジェクトの管理上の性質ではない。だから軸をオブジェクト1本に固定する。

## 1. メニュー項目はオブジェクトで立てる

**1 オブジェクト = 1 メニュー項目。同じオブジェクトを2箇所に出さない。**

| ❌ 項目として立てない | 理由 | ✅ どうするか |
|---|---|---|
| 動詞（「新規受付」「申請する」） | 操作であってオブジェクトではない | オブジェクトの画面に置く主アクション（ボタン）にする（§7） |
| 役割（「admin メニュー」「管理者向け」） | 役割は分類軸ではない（§2） | 権限で項目の表示/非表示を切る |
| データの性質（「マスタ」「トランザクション」） | 利用者の関心事ではない | 設定に属するなら「設定」へ（§3）、業務オブジェクトならトップに置く |
| 表示形式（「一覧」「カレンダー」） | 同じオブジェクトの別ビュー | 画面内のビュー切替にする |

> **同じオブジェクトが2つのグループに現れていたら、グループの切り方が間違っている。**
> 例: 「スタッフ」がシフト関連のグループと人員設定のグループの両方にある状態。
> これは「シフト」というグループがオブジェクトではなく**業務プロセス**で切られているために起きる。
> スタッフは1項目にして、シフトはスタッフ画面の中のビューにする。

## 2. 権限は分類軸ではない

**ロールごとにメニューツリーを組み替えない。** ツリーは1つで、権限は**項目の表示/非表示**にだけ効かせる。

```ts
// NG: ロールごとに別のツリーを返す。同じオブジェクトの定義が role の数だけ増殖し、
//     片方だけ項目が足される・消えるといったズレが必ず起きる
if (role === "viewer") return VIEWER_MENU;
return ADMIN_MENU;

// OK: ツリーは1つ。項目ごとに可視条件を持つ
const MENU = [
  { label: "顧客", href: "/customers" },
  { label: "売上", href: "/sales", visible: canViewSales },
];
```

### 2-1. スコープで項目を分けてよい。ただしラベルを揃える

「自分のもの」と「全体（管理側）」は**別の仕事**なので、**項目を分けてよい**。
ただし分けるなら、**同じオブジェクトであることがラベルから読み取れること**。

ルールは2つだけ:

1. **語幹（オブジェクト名）を完全に一致させる**
2. **スコープを示す接尾辞は `管理` に固定する**

| スコープ | ラベル | 例 |
|---|---|---|
| 自分のもの | オブジェクト名そのまま | `経費申請` / `支給明細` |
| 全体・管理側 | `<オブジェクト名>管理` | `経費申請管理` / `支給明細管理` |

**`一覧` を接尾辞に使わない。** 「一覧」は表示形式であってスコープではない（自分の側も一覧で表示される）。
`経費申請` と `経費申請一覧` が並んでいても、後者が「全体を管理する画面」だとは読み取れない。

**語幹をズラさない。** `支給明細`（自分）に対して `給与管理`（全体）のように語幹が変わると、
同じオブジェクトだと気づけない。`支給明細` / `支給明細管理` に揃える。

> 分けた2項目は**同じグループに隣接して置く**。離れたグループに置くと、結局ツリーが
> 役割で分断されたのと同じ状態になる。

## 3. 設定は末尾に1つ

**設定系のグループを複数作らない。** 「設定」を1つだけ置き、その中でオブジェクト別に並べる。

| ❌ | ✅ |
|---|---|
| 料金マスタ / 人員マスタ / 基本マスタ / システム設定 / 管理ツール が並列 | `設定` 1つ。中に コース・料金 / スタッフ / 支払方法 / 営業時間 … |

「マスタ」と「設定」の区別は**実装都合**（マスタテーブルかどうか）であって、
利用者から見ればどちらも「普段は触らない、変えると全体に効くもの」でしかない。

設定は**必ずメニューの末尾**に置く。使用頻度が最も低く、かつ探すときは「一番下」と決まっている方が速い。

## 4. 階層は2段まで

**グループ > 項目 の2段で止める。3段目を作らない。**

3段目が欲しくなったら、それは**画面内のタブ・セクションに降ろすべきもの**。
メニューの3段目は、開かないと見えない・現在位置が分からない・モバイルで操作しにくい、と
いいことがない。

```
OK:  設定 > 営業時間
NG:  設定 > 時間設定 > 営業時間
     → 「時間設定」画面を作り、その中のタブで 営業時間 / 早番遅番切替 / 日付切替 を出す
```

## 5. 親項目に固有の画面を持たせない

**子を持つ項目は開閉するだけ。href を持たせない。**

親が href を持ち、かつその href が子のどれかと同じだと、**同じ画面がメニューに2回現れる**。
利用者はどちらを押せばいいか判断できず、片方を押したときだけ選択状態の表示がズレる。

```ts
// NG: 親と子が同じ画面を指す
{ label: "売上", href: "/sales/summary", children: [
    { label: "月報", href: "/sales/summary" },   // ← 親と同じ
] }

// OK: 親は開閉だけ
{ label: "売上", children: [
    { label: "日報", href: "/sales/daily" },
    { label: "月報", href: "/sales/summary" },
] }
```

子を持たない項目は当然 href を持つ。**「子があるなら href なし」が原則。**

## 6. 1グループ 7 項目まで

グループ内の項目が **7 を超えたら、オブジェクトの切り方を疑う**。
たいていは「本来1つのオブジェクトの設定項目」がバラバラに項目化されている。

```
NG: 設定 > 営業時間 / 早番遅番切替時間 / 日付切り替え時間 / ポイント設定 /
          ポイントカレンダー / 入会金 / 計算設定 / 表示項目設定 / 除外年月 / …（12個）

OK: 設定 > 営業時間（中のタブで 営業時間・早番遅番・日付切替）
         > ポイント（中のタブで ポイント設定・カレンダー）
         > 料金計算（中のタブで 入会金・計算設定・除外年月）
         > 表示項目
```

項目を減らすのではなく、**関連するものを1オブジェクトに束ねて画面内のタブにする**（§4 と同じ動き）。

## 7. 動詞はメニューに出さない

「新規作成」「申請する」「スキャンする」はメニュー項目ではない。
**オブジェクトの画面を開いて、そこにある主アクション**として置く。

| ❌ メニュー項目 | ✅ 置き場所 |
|---|---|
| 新規受付 | `受付` 画面の主アクション（`Button`、[components.md](./components.md)） |
| QR スキャン | `受付` 画面のアクション、または受付作成フロー内の手段 |

例外は**そのアクション自体が独立した業務**になっている場合（例: 複数オブジェクトを横断して
処理する「振込作業」）。この場合は動詞ではなく**その業務のオブジェクト名**を探して項目名にする。

## 8. 並び順

1. **使用頻度の高い順**。毎日開くものを上に置く
2. 業務の流れがあるならその順（受付 → 顧客 → 売上）
3. **設定は必ず末尾**（§3）
4. グループ名は**名詞**にする（「売上管理」ではなく「売上」。§7 と同じ理由で動詞・サ変名詞を避ける）

アルファベット順・五十音順にしない（利用者は名前ではなく「いつもの位置」で探す）。

## 9. レビュー用チェックリスト

メニューを追加・変更する差分に対して当てる。

- [ ] 追加した項目は**オブジェクト（名詞）**か（動詞・役割・データの性質になっていないか）
- [ ] そのオブジェクトは**既にメニューのどこかに無い**か（2箇所目になっていないか）
- [ ] ロールごとにツリーを分岐させていないか（`visible` で表示制御しているか）
- [ ] スコープで分けたなら、**語幹が一致**し接尾辞が `管理` になっているか（`一覧` を使っていないか）
- [ ] 設定系を新しいトップレベルグループとして足していないか（既存の `設定` に入れたか）
- [ ] **3段目**を作っていないか
- [ ] 子を持つ項目に **href を付けていない**か
- [ ] グループ内が **7 項目**を超えていないか
- [ ] 設定が末尾にあるか

## 付録: 既存プロダクトで観測した症状（2026-09-12 棚卸し）

新規に作るときの反面教師として残す。既存の全面改修は強制しない（**触った画面のついでに直す**）。

| 症状 | 具体例 | 該当する原則 |
|---|---|---|
| 同一オブジェクトが2グループに出現 | 「スタッフ」がシフト系グループと人員設定グループの両方にある | §1 |
| 項目の重複 | 同じ設定画面が、設定グループの子と単独項目の両方に存在 | §1 |
| 親と子が同じ画面 | 「売上」グループの親 href と子「月報」の href が一致 | §5 |
| 設定系が5グループに散乱 | 料金マスタ / 人員マスタ / 基本マスタ / システム設定 / 管理ツール | §3 |
| 1グループの肥大 | 設定グループの子が12項目 | §6 |
| 役割でツリーを別定義 | 閲覧専用ロールのときにメニュー全体を別の配列で返す | §2 |
| 3段階層 | グループ > 項目 > 子項目 | §4 |
| スコープのラベル不統一 | `経費申請` ⇄ `経費申請一覧`、`支給明細` ⇄ `給与管理`（接尾辞も語幹も不統一） | §2-1 |
