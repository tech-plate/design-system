# レイアウト

画面の骨格（ブレークポイント・幅・地色・重なり・押せる領域）のルール。
**骨格はレイアウト側で 1 回だけ決め、各ページで作り直さない。**

余白の値は [spacing.md](./spacing.md)、文字と行長は [typography.md](./typography.md)、
色は [color.md](./color.md)、ナビの組み立ては [navigation.md](./navigation.md) を参照。

## 1. ブレークポイント

**Tailwind 標準のブレークポイントを使う。** `md` と `lg` の値は書き換えない。

| ブレークポイント | 幅 | 用途 |
|------------------|-----|------|
| （なし） | 〜767px | **スマホ**として設計する |
| `md` | 768px〜 | **デスクトップ**として設計する。主な切り替えはここ 1 本 |
| `lg` | 1024px〜 | サイドバーの出し分けなど、**骨格**の切り替え |

> 根拠: デジタル庁デザインシステムも切り替えは 768px の 1 本。

### 1-1. 使う段は `md` と `lg` だけ

- **`sm` `xl` `2xl` は使わない。** 切り替え点が増えるほど確かめる幅が増え、間の幅の崩れを見落とす。
- `lg` より広い画面で行長が伸びすぎるのは、段を足さずに最大幅（§2）で抑える。
- スマホの中の幅の差（320〜767px）は、段で分けずに `flex-wrap`・`min-w-0`・`w-full` などで流す。

### 1-2. テーブルはスマホでカード表示にする

**`md` 未満では `<table>` を出さず、1 行を 1 件のブロック（カード表示）にする。**
表を `overflow-x-auto` で横に流すと、右の列が画面の外に隠れ、縦スクロールの途中で横にも動かすことになる。
§7（横スクロールを出さない）と同じ理由で、スマホの一覧は縦 1 方向だけで読めるようにする。

| 要素 | 規定 |
|------|------|
| 出し分け | 同じデータから、表を `hidden md:block`、カード表示を `md:hidden` で出す。幅を JS で読んで出し分けない（サーバ描画と食い違い、読み込み直後にちらつく） |
| 入れ物 | 表をカードに入れていた画面（to B。§3）は、そのカード（padding `none`）の中を `divide-y divide-border` で 1 件ずつ区切り、各件を `p-4` にする。カードの中にカードを入れない。表がカードの外にあった画面は、1 件を 1 枚の Card（padding `sm`）にし、`space-y-4` で並べる |
| 見出し（1 行目） | **その行を見分ける列を 1 つ**（氏名・案件名・タイトルなど。表で先頭に置いていた列、または詳細へのリンクにしていた列）。`font-semibold text-foreground`、長ければ折り返す（`truncate` しない） |
| 状態 | ステータスの列は見出しのすぐ下に StatusBadge（[components.md](./components.md) §5）で置く |
| 残りの列 | 状態の下に `text-sm` で並べる。値だけで意味が分かる列（日付・金額・件数）は項目名を省き、分からない列は項目名を値の上に置く（[components.md](./components.md) §15 と同じ縦積み。項目名を左・値を右にしない） |
| 列数 | **見出しを含めて 5 列まで**（見出し・状態・残り 3 つ）。載らない列は詳細画面で見せる。詳細画面が無い一覧で収まらないなら、表のほうの列も多すぎないかを見直す |
| 行アクション | **見出しの行の右端に 1 つだけ。** 操作が 2 つ以上なら `…` のメニュー（[components.md](./components.md) §16）にまとめる。大きさは `size-11`（スマホは指で押すので、§5 の to B の 32px の例外を使わない） |
| 詳細への遷移 | 表で行を押して詳細へ移っていた一覧は、**見出しをリンクにし、`after:absolute after:inset-0` で押せる範囲を 1 件全体に広げる**（1 件の箱に `relative`）。行アクションのボタンは `relative` を付けてリンクの上に出す。1 件全体を `<a>` で包まない（リンクの中にボタンが入る） |
| hover | 押せる 1 件は表の行と同じ `hover:bg-foreground/5`（[components.md](./components.md) §1-6） |
| 並び順・件数 | 表と同じ。並べ替え・絞り込み・ページ送りの操作も表と共通の部品を使う |

例外として、**行と列の両方に意味がある表**（予定表・料金や機能の比較表・クロス集計）はカードに崩さない。
崩すと列どうしを見比べられなくなるので、表のまま親を `overflow-x-auto` で包む（[components.md](./components.md) §12。ページ全体は横に動かさない）。
`md` 以上の業務画面で幅の広い一覧の表は、§7-1 のとおり枠の中だけで横スクロールさせる（ページ全体は横に動かさない）。

## 2. コンテンツの最大幅

| 画面 | 規定 |
|------|------|
| 読み物・案内ページ | 最大幅を付けて中央寄せ（`mx-auto max-w-6xl`） |
| 業務画面の一覧・テーブル | 幅いっぱいでよい |
| 本文の行長 | ページの最大幅とは別に、本文の親で抑える（[typography.md](./typography.md)） |

`max-w-6xl`（1152px）は、デジタル庁デザインシステムの 1120px に最も近い Tailwind 標準値。
`max-w-[1120px]` のような任意値にしない。

## 3. ページの地色

地色の切り方は、**カード型の画面かどうか**で決める。
**to B の管理画面は原則カード型にする。** 指標カードとテーブルが混在する画面でも、テーブルをカードに入れる。

| 画面の作り | 地色 | カード |
|------------|------|--------|
| カード型（内容を白いカードに載せる） | `bg-muted` | `bg-card border border-border rounded-lg` |
| カードを使わない（文書型など。to B の管理画面には使わない） | `bg-background` | — |

- **1 つのアプリの中で混ぜない。** 地色はレイアウト側で 1 回だけ指定し、各ページで変えない。
  画面ごとに地色が変わると、別のサービスに移ったように見える。
  管理画面と利用者向け画面のように入口が分かれているものは、それぞれで決めてよい。
- カードに影を付けない（[components.md](./components.md)）。

## 4. 重なりの順序（z-index）

| 値 | 対象 |
|----|------|
| 100 | 固定・追従するナビ（ヘッダー、ボトムタブバー） |
| 200 | モーダル・ドロワー |
| 250 | メニュー・ポップオーバー（[components.md](./components.md) §16）。モーダルの中から開いても潜らないようモーダルより上、そこから開く確認ダイアログより下 |
| 300 | モーダルの中から開く確認ダイアログ |
| 400 | トースト（[components.md](./components.md) の Toast）。モーダルを開いたまま出る完了通知が暗幕の下に潜らないよう、モーダルより上 |

- **Tailwind 既定の `z-50` 等に丸めない。** ナビより下にモーダルが潜ると暗幕がナビにかからず、
  モーダルのフッターのボタンがナビに隠れて押せなくなる（実例がある）。
- Tailwind v4 は `z-100` `z-400` のように整数をそのまま書ける。v3 は `z-[100]` のように書く。
- 環境表示など、最前面に出す単発の UI はこの表の外で扱う。

## 5. タッチターゲット

**押せる要素は最小 44×44px。** 見た目のアイコンは小さくてよく、**押せる領域**を 44px にする。

| 要素 | クラス |
|------|--------|
| ボタン・リンク・リスト行 | `min-h-11` |
| アイコンだけのボタン | `size-11`（中のアイコンは小さくてよい） |

| 画面 | 例外 |
|------|------|
| to C | **例外なし** |
| to B | 密な一覧の中の行アクションに限り 32px（`h-8`）まで可 |

文中のリンク（文章の行の中にあるもの）は行の高さに従い、この規定の対象外とする。

## 6. 暗幕

モーダル・ドロワーの背面は **`bg-overlay/50`**。`bg-black/50` 等の生カラーにしない（[color.md](./color.md)）。

## 7. 横スクロールを出さない

ページ全体の横はみ出しは **`overflow-x: clip`** で切る（Tailwind では `overflow-x-clip`）。

**`overflow-x: hidden` にしない。** `html` / `body` に `hidden` を付けるとそこがスクロールコンテナになり、
`position: sticky` のヘッダーが追従しなくなる。

はみ出しの原因そのもの（固定幅の要素、ネイティブの日付入力等）は個別に直す（[forms.md](./forms.md)）。
スマホの一覧の表は横に流さず、カード表示にする（§1-2）。

### 7-1. 業務画面の幅の広い表（to B）: 枠の中だけで横スクロールする

**ページ全体を横スクロールさせない。** 幅の広い表は、表を包む枠の中だけで横にスクロールさせる。
縦は表の中でスクロールさせず、画面ごとスクロールする（表の高さを `max-h-*` や `calc(100dvh - …)` で絞ると、
表の中と画面全体の二重スクロールになり、ホイールやスワイプがどちらを動かすか分からなくなる）。

枠を `overflow-x-auto` にすると、その枠がスクロールの基準になり、`position: sticky` の見出し行が画面の上端に貼り付かなくなる
（`sticky` は一番近いスクロールする祖先に対して効く。`overflow-x` だけを `auto` にしても縦も基準になる）。
そこで見出し行は `sticky` ではなく、**画面の縦スクロールに合わせて JS で `position: relative` の `top` をずらす**。

| 項目 | 規定 |
|------|------|
| 表の枠 | `overflow-x-auto overflow-y-hidden`（横だけ枠の中でスクロール）。`max-h-*` を付けない |
| 見出し行 | `<thead>` を `relative` にし、`top` を CSS 変数（例 `--x-head-shift`）で渡す。値は「枠の上端が貼り付け位置より上に出た分」を、表の下端を越えない範囲で JS が書く（スクロール・リサイズのたびに測る）。`transform` でずらさない（`border-collapse` の表で罫線や背景の描画がずれる）。重なりは本文の固定列より上にする |
| 見出しのセルの罫線 | **見出しのセルに上の罫線を付けない。** `border-collapse` の表でずらした見出し行に上の罫線があると、Chrome がその上端に下の行を透けて描く。外周の線は枠の `border` で引く |
| 貼り付け位置 | 上端の帯の高さ（帯の下に保存ボタン等の見出しを貼り付ける画面はその高さも足す）。高さは CSS 変数でレイアウトから渡し、ページごとに px を書かない |
| 先頭の列 | 固定するなら `sticky left-0`（枠の左端で止まる。枠が横のスクロールの基準なので `sticky` のままでよい） |
| 横スクロールバー | **画面の下端に貼り付ける。** 枠自身のスクロールバーは隠し、`sticky bottom-0` の代わりのバー（幅を枠の `scrollWidth` に合わせ、スクロール位置を枠と同期する）を出す。表の途中を見ていても横に動かせるように。はみ出していないときは出さない。代わりのバーはマウス用の複製なので `aria-hidden` |
| キーボード | はみ出しているときだけ枠を `role="region"` + `aria-label` + `tabIndex={0}` にし、矢印キーで横に動かせるようにする |
| `main` / `html` / `body` | §7 どおり `overflow-x-clip`。`hidden` は付けない |

- `md` 未満の一覧は §1-2 のカード表示のまま。行と列の両方に意味がある表（予定表・比較表）は `md` 未満でもこの枠で横スクロールさせる。
- 採用: kanrichan（#1302 / PR #1303、2026-10-30。`apps/admin/src/components/ui/scrollable-table-container.tsx`）。
- ※ 0.8.x までの「ページ全体を横スクロールさせてよい」例外（#9）は 0.9.0 で廃止した。横に送ると表の周りのカードやページ上部の操作まで一緒に流れ、表がカードの外まで伸びて崩れて見えるため。

## 8. やらないこと

- ❌ `md` / `lg` の値を書き換える → §1
- ❌ `sm:` `xl:` `2xl:` で段を足す → `md` と `lg` だけ（§1-1）
- ❌ スマホで一覧の表を `overflow-x-auto` の横スクロールで済ませる・列を間引いただけの狭い表にする → カード表示（§1-2）
- ❌ スマホのカード表示で、1 件の中に行アクションのボタンを並べる・1 件全体を `<a>` で包む → §1-2
- ❌ ページごとに地色を変える・カード型と非カード型を混ぜる → §3
- ❌ `z-50` `z-[9999]` のような場当たりの z-index → §4 の表から選ぶ
- ❌ アイコンの見た目の大きさ（`size-4` 等）をそのまま押せる領域にする → §5
- ❌ `overflow-x-hidden` で横はみ出しを隠す → `overflow-x-clip`（§7）
- ❌ 表の高さを絞って表の中で縦にスクロールさせる（二重スクロール） → 画面全体でスクロール（§7-1）
- ❌ 幅の広い表でページ全体を横スクロールさせる → 枠の中だけで横スクロール（§7-1）
- ❌ 枠の中で横スクロールする表の見出し行を `transform` でずらす・見出しのセルに上の罫線を付ける → `position: relative` の `top`（§7-1）
