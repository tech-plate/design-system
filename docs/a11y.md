# アクセシビリティ

全画面に共通するアクセシビリティの基準。**目標の水準はここで決め、各 docs に書いたルールは §2 の索引で場所だけを示す。** §3 以降は、どの docs にも無い横断のルール。

## 1. 目標水準

| 項目 | 規定 |
|------|------|
| 適合の目標 | **JIS X 8341-3:2016 の適合レベル AA 相当** |
| 実装時に参照する基準 | **WCAG 2.2 の AA**。2.2 で増えた基準（下表）も満たす |
| 部品の作り方 | WAI-ARIA Authoring Practices Guide（APG）のパターンに従う |

JIS X 8341-3:2016 は WCAG 2.0 と同じ内容なので、WCAG 2.2 AA を満たせば JIS の AA も満たす（DADS に倣う）。

| 2.2 で増えた基準（A・AA） | このデザインシステムでの対応 |
|------------------------|------------------------------|
| 2.4.11 フォーカスが隠れない | 追従するヘッダー・タブバーの下にフォーカスが潜らないようにする（§5-1） |
| 2.5.7 ドラッグ操作 | ドラッグだけの操作を作らない（§5-4） |
| 2.5.8 ターゲットサイズ（最小 24px） | 44px（to B の密な一覧は 32px）で満たしている（[layout.md](./layout.md) §5） |
| 3.2.6 一貫したヘルプ | ヘルプ・問い合わせへの導線を置くなら、全画面で同じ位置に置く |
| 3.3.7 冗長な入力 | 同じ内容を 2 度入力させない（§14） |
| 3.3.8 認証（最低限） | パズル・文字の書き写しだけのログインにしない（§14） |

- デザインシステムで担保できるのは部品と骨格まで。画面ごとの中身（画像の代替テキスト、見出しの文言、読み上げの順）は各プロダクトが確保する。

## 3. ページの骨格

| 項目 | 規定 |
|------|------|
| 言語 | `<html lang="ja">`。英語の長い引用など、まとまった外国語の箇所だけ `lang="en"` を付ける |
| ページタイトル | **画面ごとに固有の `<title>`**。「画面名 \| サービス名」の順。画面名は `<h1>` と同じ語。SPA の画面遷移でも書き換える |
| ランドマーク | `<header>` / `<nav>` / `<main>` / `<footer>`。**`<main>` は 1 画面に 1 つ** |
| 複数の `<nav>` | それぞれ `aria-label` で区別する（「メインメニュー」「パンくずリスト」） |
| 本文へのスキップ | サイドバーのある画面は、先頭に「本文へ移動」のリンクを置く（`sr-only focus:not-sr-only`）。行き先は `<main>` |

- ❌ `<title>` を全画面で同じサービス名にする。タブの一覧・履歴・読み上げで画面を区別できない。

## 4. 見出し

- `<h1>` は 1 画面に 1 つ（§2 の索引）。モーダルのタイトルは `<h2>`（[components.md](./components.md) §7-2）。
- **見出しのレベルを飛ばさない。** `<h1>` の次は `<h2>`、`<h2>` の中は `<h3>`。
- **見た目のサイズと見出しのレベルを切り離す。** レベルは文書の構造で決め、サイズは [typography.md](./typography.md) の用途マップで決める。
  小さく見せたい `<h2>` は `text-base` を当てればよく、`<h4>` に下げない。
- ❌ 太字の `<p>` を見出しに見せる。✅ 見出しタグで書き、クラスでサイズを決める。
- ❌ 強調のためだけに見出しタグを使う。

## 5. キーボード操作

**マウス・タッチでできる操作は、すべてキーボードだけでもできるようにする。**

### 5-1. フォーカスの移動

- **Tab の順 = DOM の順 = 見た目の順。** 読む順に DOM を書けば、Tab の順は自然に揃う。
- **`tabindex` に正の値を使わない。** 使えるのは `0`（フォーカスできない要素を Tab に入れる）と `-1`（スクリプトからだけフォーカスする）。
- ❌ `<div>` / `<span>` に `onClick` だけを付ける。キーボードでも読み上げでも押せない。✅ `<button>`、遷移なら `<a href>`。
- 追従するヘッダー・タブバーの下にフォーカスが潜らないよう、`<html>` に `scroll-pt-16`、タブバーのある画面は `max-lg:scroll-pb-[var(--tabbar-offset)]` を付ける（2.4.11）。

### 5-2. 閉じ込めと戻し

- **フォーカスを閉じ込めない。** Tab で入れた場所からは Tab / Shift+Tab で出られるようにする。
- 例外は Modal・確認ダイアログ・ドロワー。開いている間だけ中に閉じ込める（[components.md](./components.md) §7-2）。
- **閉じたら、開いた要素にフォーカスを戻す**（Modal・ドロワー・Menu すべて）。戻さないとフォーカスがページの先頭に飛び、どこまで操作したか分からなくなる。
- 開いた要素が閉じた結果消えている（行を削除した）ときは、その次の行か一覧の見出しに戻す。

### 5-3. Esc で閉じるもの

ドロワー・ポップオーバー・ツールチップは Esc で閉じる。Modal・確認ダイアログ・Menu は各部品の規定に従う（[components.md](./components.md) §7-1・§7-2・§16-3。確認ダイアログは Esc で閉じない）。

### 5-4. ドラッグ

- 並べ替え・範囲選択などを**ドラッグだけ**で行わせない。「上へ」「下へ」のボタンやメニューなど、1 回のタップ・キー操作で済む手段を併置する。

## 6. 読み上げの順と見た目の順

**見た目の順は DOM の順で作る。CSS で見た目だけを入れ替えない。**

- ❌ `order-*`・`flex-row-reverse` / `flex-col-reverse`・`absolute` の配置で、DOM と違う順に見せる。読み上げと Tab の順だけが元の順に残る。
- ✅ 見た目の順を変えたいときは DOM の順を入れ替える（確認ダイアログのボタン。[components.md](./components.md) §7-4）。
- 幅で並びを変える必要があるときは、その幅ごとの読む順に DOM を合わせる（例: ボタン行の `md:contents`。[components.md](./components.md) §2-3）。

## 7. 名前・役割・状態

**ネイティブ要素で足りるときは ARIA を足さない。** `<button>` に `role="button"`、`<nav>` に `role="navigation"` を重ねない。

| 場面 | 規定 |
|------|------|
| 開閉するもの（Menu・アコーディオン・通知の一覧） | 開くボタンに `aria-expanded` |
| 必須の入力 | `required`（`*` は見た目の印） |

- **見えている文字があるボタンは、`aria-label` で別の名前に上書きしない。** 付けるときは見えている文字で始める（「通知（未読 3 件）」。2.5.3）。
- 状態は見た目のクラスと ARIA の属性で二重に持たない。属性をクラスの条件にする（`aria-pressed:` / `aria-[current=page]:` 等）。

## 8. 状態の通知

### 8-1. フォームのエラーは aria-live で読み上げない

検証エラーは `aria-live` / `role="alert"` で読み上げず、`aria-describedby` とフォーカスの移動で伝える（作り方は [forms.md](./forms.md) §5・§5-1・§5-2）。
入力中にエラーが割り込んで読まれると、打っている内容が聞き取れなくなる（DADS も同じ方針）。

### 8-2. aria-live を使う場面

**フォーカスを動かさずに画面の一部が変わり、その変化を知らないと次に進めないときだけ**使う。

| 場面 | 使うもの |
|------|----------|
| 操作の完了（トースト） | `role="status"`（[components.md](./components.md) §9-2） |
| 絞り込み・検索の結果件数が変わった | 件数の文に `role="status"` |
| ボタン以外から始まった読み込みが終わった | 終わったことを `role="status"` で 1 回だけ |
| 操作の失敗（保存できなかった等） | `role="alert"`（[components.md](./components.md) §4-2） |

- ライブリージョンは**先に DOM に置き、中身だけを入れ替える**（後から足した要素は読まれないことがある）。
- ❌ 入力のたびに変わる文字数カウンターや、自動保存のたびの「保存しました」を読み上げる。

## 9. 色だけで伝えない

- 状態・選択・エラーは、**色に加えて文言・アイコン・太さ・下線のどれか**でも示す。
- グラフは色の凡例だけに頼らず、系列名を線の近くに書くか、値を表でも出す。

## 10. 画像

| 画像 | 規定 |
|------|------|
| 意味を持つ画像（写真・図） | `alt` に**画像が伝えている内容**を書く。「画像」「写真」と書かない |
| リンク・ボタンの中の画像だけの要素 | `alt` に**行き先・操作**を書く |
| 飾り（隣の文字と同じことを言っている、雰囲気だけの画像） | `alt=""`。`alt` 属性ごと消さない（ファイル名が読まれる） |
| アイコンの SVG | `aria-hidden="true"`（[components.md](./components.md) §1-4） |
| グラフ・複雑な図 | `alt` は要旨だけにし、数値は本文か表で出す |

## 11. 動き

- **`prefers-reduced-motion` を尊重する。** アニメーションには `motion-reduce:` で止めるか、移動をフェードに置き換える版を用意する（既存の例: [components.md](./components.md) §8-2・§8-3・§9-2）。
- **自動で動き続けるもの（自動送りのカルーセル、流れる文字）を置かない。** やむを得ず置くなら、一時停止のボタンを付ける。
- **点滅させない。** 1 秒に 3 回を超えて光るものは作らない。

## 12. 拡大とリフロー

| 確認 | 規定 |
|------|------|
| 文字の拡大 | ブラウザの拡大 200% で、文字の切れ・重なり・操作できない箇所が出ない |
| リフロー | 幅 320px 相当（1280px 幅で 400%）で、ページ全体に横スクロールが出ない。表・コードなど 2 次元のものだけは親の `overflow-x-auto` でよい（[components.md](./components.md) §12） |
| ピンチズーム | 禁止しない。viewport に `maximum-scale` / `user-scalable=no` を書かない |

- `overflow-x-clip`（[layout.md](./layout.md) §7）は最後の安全策。はみ出した内容が切れて読めなくなっていないかを、320px で確かめる。
- 文字を入れる箱は高さを固定しない（`h-*` ではなく `min-h-*`）。拡大や行間の変更で文字があふれる。
- iOS の入力時の拡大は、viewport ではなく入力欄の 16px で防ぐ（[typography.md](./typography.md) §1-2）。

## 13. 時間制限

- 自動ログアウトなどの時間制限は、**切れる前に知らせて、ワンタップで延長できる**ようにする（知らせてから 20 秒以上の猶予）。
- **トーストに唯一の操作手段を載せない。** トーストは自動で消え、キーボードでは届きにくい（[components.md](./components.md) §9-2）。

## 14. 入力と認証

- **貼り付けを禁止しない。** 確認用のメールアドレス・パスワード欄も含む。
- **同じ内容を 2 度入力させない**（3.3.7）。前の手順で入力した値は引き継ぐか選べるようにする（「請求先は配送先と同じ」のチェック）。確認用の再入力欄を置かない。
- **ログインに記憶・パズル・文字の書き写しを求めない**（3.3.8）。パスワード管理ツールで入力できるようにし、画像認証を置くなら別の手段を併置する。

## 15. 確認方法

実装したら、少なくとも次を行う。**自動検査で見つかるのは問題の一部だけ**で、キーボードと読み上げの確認は省略できない。

| 確認 | 見るもの |
|------|----------|
| キーボードだけで一通り操作する | 全操作ができるか、Tab の順、フォーカスの見え方、閉じたあとの戻り先、Esc |
| macOS の VoiceOver・iOS の VoiceOver で主要画面を読む | 見出し・ランドマークの一覧、ボタンの名前、状態、通知の読み上げ |
| ブラウザの拡大 200%・幅 320px | 切れ・重なり・横スクロール |
| axe（DevTools 拡張）で自動検査 | 名前の欠け、ARIA の誤用、コントラスト |
| `pnpm check`（トークンを変えたとき） | トークンのコントラスト（[color.md](./color.md) §8） |

## 16. レビュー用チェックリスト

差分行を対象に当てる。部品ごとの項目は [components.md](./components.md) §17 を併せて当てる。

### ページ・見出し

- [ ] `<html lang="ja">` で、画面ごとに固有の `<title>` があるか
- [ ] `<main>` が 1 つで、複数の `<nav>` が `aria-label` で区別されているか
- [ ] `<h1>` が 1 つで、見出しのレベルを飛ばしていないか（サイズのためにレベルを変えていないか）

### キーボード・順序

- [ ] `<div>` / `<span>` にクリックだけを付けていないか
- [ ] `tabindex` に正の値を使っていないか
- [ ] `order-*`・`*-reverse`・`absolute` で見た目の順だけを入れ替えていないか
- [ ] Modal・ドロワーを閉じたら、開いた要素にフォーカスが戻るか
- [ ] ドラッグだけの操作が無いか

### 名前・状態・通知

- [ ] 開閉するものに `aria-expanded` があるか
- [ ] ネイティブ要素に同じ意味の `role` を重ねていないか
- [ ] 検証エラーに `aria-live` / `role="alert"` を付けていないか
- [ ] `aria-live` を §8-2 の場面以外で使っていないか

### 画像・動き・拡大

- [ ] 意味のある画像に内容の `alt`、飾りに `alt=""` があるか
- [ ] アニメーションに `motion-reduce:` の手当てがあるか。自動で動き続けるもの・点滅が無いか
- [ ] viewport に `maximum-scale` / `user-scalable=no` を書いていないか
- [ ] 200% 拡大・幅 320px で切れ・横スクロールが出ないか

### 時間・入力

- [ ] トーストにだけ置いた操作が無いか
- [ ] 貼り付けを禁止していないか。同じ内容の再入力を求めていないか
